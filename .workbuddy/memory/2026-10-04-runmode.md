## 做了什么
新增 `src/runmode.rs`：
- `RunMode` 枚举 6 值，命名对齐 OpenClash：fake-ip / redir-host /
  fake-ip-tun / redir-host-tun / fake-ip-mix / redir-host-mix
- `resolve()` 是**唯一事实来源**，拆成两个正交维度：
  `fake_ip: bool` × `firewall: Clashx | Mihomo | Both`（+ tun_enable）
- schema 新增：`Config.run_mode` / `Sniffer.force_dns_mapping` /
  `Tun.endpoint_independent_nat`
- 渲染器不再match `transparent.mode`，全部由 run_mode 驱动
- 新增 CLI：`run-mode show` / `run-mode set <mode>`

## 抄自 OpenClash 的关键点
1. **UI 一个枚举 → 脚本立刻拆两个变量**（init.d/openclash:485-510）
2. **redir-host 必须开 `sniffer.force-dns-mapping`**（yml_change.sh:509）
   —— 没这行 redir-host 下所有域名规则静默失效
3. TUN 模式固定开 `endpoint-independent-nat`（yml_change.sh:524）
4. 主动 `delete('iptables')` / `delete('ebpf')` / `delete('auto-redir')`
   防止 mihomo 与 clashx 抢 chain

## 真机新踩的坑（都写进代码注释了）
### 1. auto-route=false + auto-redirect=true → 内核 panic
`listener/sing_tun/server.go:671` nil pointer，systemd status=2。
六组组合逐一实测，只有这一组炸。auto-redirect 依赖 auto-route 的路由集。
★ `mihomo -t` 对这组**校验通过**，只有真启动才炸 —— -t 只能验合法性。

### 2. ProtectSystem=strict 下建不起 TUN 设备
放宽到 `full` + 加`DeviceAllow=/dev/net/tun rw` 后正常。
同一份配置手动 root 跑也正常，极易误判为配置问题。

### 3. 重构时的自身失误（值得记）
用「标记搜索 + 大段替换」改渲染器，范围算错把 `proxies:` / `dns:` 段
一起删了 —— 症状是渲染产物缺 proxies、proxy-group 引用不存在的节点名。
**教训：改Rust 源码用行号精确定位，替换后必须断言关键段还在。**
（已加 `assert'm.insert("proxies".into()' in s` 形式的断言）

### 4. Rust 测试函数名不能含空格
中文可以、空格不行（missing parameters）。批量正则去空格解决。
